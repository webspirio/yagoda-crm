# Ягода — прийомка ягід

**Живе демо → https://webspirio.github.io/yagoda-crm/**

Робочий макет CRM для мережі пунктів прийомки ягід. Зроблений під конкретну розмову з клієнтом:
чотири точки, розрахунок чистої ваги з відніманням тари, ціна дня з коригуванням, залишки за
постачальниками з привʼязкою до дати здачі, зведена аналітика для власників.

Це **демо**, а не продакшн: сервера немає, усе живе в `localStorage` браузера. Але логіка
розрахунків справжня — цифри сходяться, записи створюються, залишки закриваються.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Збірка: `npm run build`, попередній перегляд: `npm run preview`.

## Що всередині

| Розділ | Що показує |
|---|---|
| **Прийомка** | Ваговий термінал: брутто − тара = нетто, × ціна = сума. Вибір постачальника з підказкою по залишку, сорт із ціною дня, екранна клавіатура, квитанція з друком |
| **Каса за день** | Звірка: нараховано = видано + залишок. Окремо — гроші, видані сьогодні за ягоду попередніх днів, з розкладкою по датах |
| **Ціни дня** | Ціна на кожен сорт і кожну точку, історія змін протягом дня з причиною й автором, динаміка за 14 днів |
| **Постачальники** | Картка на людину: телефон, село, надбавка оптовику, уся історія здач і виплат |
| **Залишки** | Хто, скільки і з якої дати. Видача закриває найстаріші залишки першими (FIFO) з видимою розкладкою |
| **Журнал** | Повний реєстр сезону (~1200 квитанцій), фільтри за період / сорт / точку / людину, вивантаження CSV |
| **Зведення** | Тонаж і гроші по днях, порівняння точок, сорти за тонажем, найбільші здавальники |
| **Точки** | Чотири прийомки: частка тонажу, каса сьогодні, залишки, динаміка за 14 днів |
| **Тара і сорти** | Ваги видів тари (редагуються), вікна сезону по сортах |

## Ролі

Перемикач у лівому нижньому куті — це демо-афорданс; у бойовій системі роль дає вхід.

- **Приймальник** — лише своя точка: прийомка, каса дня, ціни, постачальники, залишки.
  Точку змінити не може, вагу тари не редагує, зведення не бачить.
- **Власник** — усі точки, аналітика, довідники, журнал.

## Демо-сценарій на 6 хвилин

1. **Прийомка → оберіть постачальника з залишком** (у списку такі позначені бурштиновою сумою
   праворуч). Одразу під полем зʼявляється «Залишок за нами … з 23.07, 25.07».
2. **Введіть брутто** (наприклад 128.4) і натисніть **+10 ящ.** — термінал сам показує тару
   16,00 кг і нетто 112,40 кг, множить на ціну дня й дає суму. Це відповідь на «щоб окремо не
   вираховувати чисту вагу».
3. **Розрахунок → «До сотні»** — видали круглу суму, різниця автоматично впала в залишок із
   сьогоднішньою датою. **Прийняти** → квитанція, її можна роздрукувати людині на руки.
4. **Каса за день** — «Нараховано − видано − залишок = 0». Нижче окремим блоком: гроші, що вийшли
   сьогодні за ягоду 31.07 і 01.08. Саме через це в Excel «видача більша за ягоду».
5. **Залишки → Видати** будь-кому — видно, які саме здачі закриваються і якими датами.
   Після видачі поверніться в **Касу за день**: сума зʼявилась у блоці боргів, а не змішалась
   із сьогоднішньою ягодою.
6. **Перемкніть роль на Власника** → **Зведення**: тонаж за 30 днів, скільки вийшло з каси,
   скільки відкритих залишків, порівняння чотирьох точок. Потім **Журнал** → «Липень»: фільтр
   за місяць відпрацьовує за одиниці мілісекунд на 1200 записах.

Бонус: натисніть пігулку **«Дані збережено»** у шапці — система переходить в офлайн. Прийомка
працює далі, нові квитанції стають у чергу («Офлайн · 1 у черзі»). Натисніть ще раз — черга
йде на сервер. Це відповідь на «під вечір усе зависає».

**Скинути демо-дані** повертає початковий стан.

## Дані демо

Сезон 6 липня — 4 серпня 2026, 4 точки, 52 постачальники, ~1200 квитанцій, ~60 т ягоди,
6 сортів із власними вікнами сезону. Генератор детермінований (`src/lib/seed.ts`) — на будь-якому
компʼютері однакові цифри.

## Стек

React 19 + TypeScript, Vite, Tailwind v4, shadcn/ui (Radix), Recharts, Zustand + persist.

## Архітектура розрахунків

Уся арифметика зібрана в `src/lib/calc.ts` — це те, що в Excel розмазано по формулах у клітинках:

- `weigh()` — брутто, тара, нетто, ціна з надбавкою, сума;
- `supplierBalance()` / `openDebts()` — скільки винні й за які саме здачі;
- `allocatePayout()` — FIFO-розподіл видачі по відкритих залишках зі збереженням дати ягоди;
- `reconcileDay()` — денна звірка з окремим розрізом «гроші сьогодні за ягоду інших днів».

Формулу не можна випадково стерти: вона одна на всю систему.

## Чого свідомо немає в макеті

Справжнього бекенду й автентифікації, прав на рівні полів, обліку продажу ягоди далі по ланцюгу,
приймання горіхів (інша специфіка), інтеграції з вагами по кабелю, SMS постачальникам.
Усе це — предмет технічного завдання, а не демо.
